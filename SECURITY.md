# Security Policy

We take the security of this repository and its users seriously. If you believe you have found a vulnerability, please report it privately so we can investigate and fix it before public disclosure.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, pull requests, or discussions.**

Send reports to [security@twelvelabs.io](mailto:security@twelvelabs.io).

### Encrypting your report

You can encrypt reports with our OpenPGP key.

- **Email:** security@twelvelabs.io
- **OpenPGP fingerprint:** `FED1 19F6 DFB8 4655 B006 A763 5DEA 5FA2 14A7 574A`
- **Public key:** available via OpenPGP keyservers for `security@twelvelabs.io`

Please verify the fingerprint before encrypting.

### What to include

Include as much of the following as you can:

- A description of the vulnerability and its potential impact
- The type of issue (for example, secret exposure, injection, authentication or authorization bypass)
- Affected files, components, or URLs
- The tag, branch, or commit where you found it
- Step-by-step reproduction instructions
- A proof of concept, if you have one
- Any suggested remediation

### What to expect

We will acknowledge receipt of your report and follow up as we investigate and work on a fix. Please give us a reasonable window to assess and remediate the issue before any public disclosure.

## Scope

This policy covers the source code, configuration, and documentation in this repository.

It does not cover:

- Other TwelveLabs products, repositories, or services (report those to [security@twelvelabs.io](mailto:security@twelvelabs.io) as well)
- Third-party dependencies (report those to the respective maintainers)
- Issues that require a private deployment, credentials, or customer data you do not own

Thank you for helping keep TwelveLabs and our users safe.
